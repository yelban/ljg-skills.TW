# Extract Workflow

把一份資訊抽成 Q-A 鏈。

## Voice Notification

```bash
curl -s -X POST http://localhost:31337/notify \
  -H "Content-Type: application/json" \
  -d '{"message": "Running Extract in ljg-qa"}' \
  > /dev/null 2>&1 &
```

輸出文本：`Running **Extract** in **ljg-qa**...`

## Step 1: 獲取內容

按輸入型別走：

| 輸入 | 工具 | 注意 |
|------|------|------|
| URL（普通網頁） | WebFetch | 需要登入的頁面用 markdown-proxy |
| arxiv 連結 | WebFetch（HTML 版） | 拿 abstract + 方法 + 實驗段 |
| PDF / 本地檔案 | Read | 大 PDF 用 pages 引數分段讀 |
| 直接文本 | 跳過 | 直接進入 Step 2 |
| 論文/書名 | WebSearch | 拿到 URL 再走 WebFetch |

確保拿到：核心論點 / 論證鏈 / 關鍵例子 / 邊界討論。

## Step 2: 找觀點骨架

讀完後沉默 30 秒，回答這一個問題：

> 這篇東西的核心論點是什麼？它怎麼把這個論點撐起來？哪幾步是關鍵轉折？

寫下：

- **核心論點**：一句話
- **3-5 個關鍵轉折**：每個轉折一句話

這是 Q 鏈的脊柱。脊柱立不起來，下面的 Q 都是浮的——回去重讀。

## Step 3: 設計 Q 鏈

每個關鍵轉折長出一個或一組 Q。Q 必須滿足：

1. 一句定義答不出來——切要害
2. 答案能在原材料裡找到根據
3. 跟前一個 Q 有繼承關係（Q2 是 Q1 答完後自然冒出來的）

Q 型別四類（動 / 對 / 因 / 界）和模式見 `../References/QuestionDesign.md`。一篇好 Q 鏈至少混合三類。

*排序規則*：按論證依賴關係，不按章節順序。原文先寫背景再寫方法是敘事需要，但 Q 鏈應該按「先問根問題，再問解法，再問代價」走。

*數量*：5-10 個 Q。少則不夠覆蓋，多則讀者疲勞。

## Step 4: 寫 A

每個 A 嚴格四段，不可省，不可亂：

```
*結論*：（一句話——能脫離上下文被抄走）

*形式化*：（用文字 + 簡單符號把思想壓成一行可視關係——見下方"形式化的寫法"）

*怎麼想到的*：
- 步驟 1（短句，只走一步推理）
- 步驟 2
- 步驟 3

*邊界*：（這個結論在什麼條件下不成立 / 論證還沒覆蓋什麼）
```

硬要求：

- **結論**：脫離上下文還能被抄走。讀者把這句話發給朋友，朋友能 get
- **形式化**：用文字 + 簡單符號（→ = ≠ + × ⊃ ⊥ 等）把思想壓成一行可視的關係——是"思想的幾何"，不是"數學的公式"。讓讀者一眼看出對應關係。詳見 `../References/QuestionDesign.md` 的"形式化的寫法"
- **論證步**：每條只走一步推理，前一步開啟後一步的口子
- **邊界**：寫「不成立的條件」，不寫「未來工作」——前者是誠實度，後者是公關辭令

### 形式化的寫法（要點）

四種常見模式：

- **等式**：`通才 = 協調員；專才 = 幹活的`
- **對比**：`舊: 大模型 = 全棧；新: 大模型 = 協調員`
- **流向**：`資料 → token → 答案 = 損失 + 浪費`
- **遞進**：`呼叫 → 介面 → 雙語熱線`

只用 ASCII + 中文。禁 LaTeX、禁複雜數學符號。一行內放完。

## Step 5: 檢查 Q 鏈方向感

通讀 Q 順序：

- **繼承**：Q1 答完，Q2 是不是自然冒出來？
- **依賴**：把 Q3 刪了，Q4 還成立嗎？

如果 Q 之間是平行的（刪一個不影響其他），重排或合併。Q 鏈是路徑，不是清單。

可以畫一張草圖（不入 Markdown，只是自己的腳手架）：

```
Q1 ─┬─→ Q2
    └─→ Q3
Q2 ──→ Q4
Q4 ──→ Q5（收口反問）
```

## Step 6: 過紅線

逐條掃：

- [ ] 每個 Q 不能用一句定義打發
- [ ] 每個 A 四段齊（結論 / 形式化 / 步驟 / 邊界）
- [ ] 形式化句一眼能看出關係——不是數學公式，不是堆術語
- [ ] Q 鏈有方向（不是並列羅列）
- [ ] 沒有「什麼是 X」型 Q
- [ ] Q 句 ≤ 20 字（一眼能掃完）
- [ ] 沒有學術腔（「值得注意的是」「綜上所述」「在……背景下」）
- [ ] A 沒有靠堆術語保平安——所有術語翻譯成具體動作或物件
- [ ] 5-10 個 Q

任何一條不過，回去改。

## Step 7: 寫檔案

獲取時間戳：

```bash
date +%Y%m%dT%H%M%S         # → identifier
date "+%Y-%m-%d %a %H:%M"   # → date 欄位
```

denote schema 檔名：`{YYYYMMDDTHHMMSS}--qa-{主題}__qa.md`

- `qa-` 字首：標記 Q-A 型別（與 ljg-paper 的 `paper-` 同構）
- 主題：核心論點的 5-10 字提煉，去標點。優先用方法名/概念名/靈魂句關鍵字
- `__qa` 字尾：keyword tag，便於 denote 搜尋

輸出路徑：`~/Documents/notes/`

寫入後報告路徑給使用者。

## 檔案結構

```markdown
---
title: {一句精煉的核心觀點——10-25 字}
subtitle: {原文標題}
date: [{YYYY-MM-DD Day HH:MM}]
tags: qa
identifier: {YYYYMMDDTHHMMSS}
source: {URL 或來源}
---
# 引子

（一段話，3-5 句：這篇東西在講什麼，為什麼值得拿出來問。帶讀者落地，不是綜述）

# Q1: {一句尖銳的問句，≤ 20 字}

  **結論**：...

  **形式化**：...（如 `A = B + C` / `舊: X → 新: Y`）

  **怎麼想到的**：
  - ...
  - ...
  - ...

  **邊界**：...

# Q2: ...

  ...

# 收口

（一句話壓住整串 Q-A：作者真正貢獻的那個東西是什麼。不是總結，是命名）
```

注意：

- 加粗用 `**bold**`（雙星號）
- 列表用 `- item`；標題使用 `#`
- 分隔用空行或層級，不用 `---`
- 程式碼使用反引號包裹

## 驗收

- **Q 切要害**：每個 Q 不能用一句定義打發
- **A 有形式化收口**：每個 A 四段齊——結論句能被抄走，形式化一眼看出關係
- **Q 鏈有方向**：刪一個 Q 後續會塌
- **不復述原文**：是骨架重建，不是段落改寫
- **中文母語**：每句默唸聽是否像中文人說話——動詞驅動、不堆術語、不學術腔
