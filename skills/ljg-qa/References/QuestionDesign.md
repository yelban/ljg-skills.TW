# Question Design

如何讓 Q 切要害，A 不散掉。

## Q 的四類（動-對-因-界）

每類對應作者論證的一個支點。一篇好 Q 鏈至少混合三類。

| 型別 | 模式 | 例 |
|------|------|---|
| *動作* | 「他是怎麼做到的？」 | 「他怎麼把 X 轉成 Y？」 |
| *對比* | 「為什麼是 A 不是 B？」 | 「為什麼用迭代而不是並行？」 |
| *因果* | 「為什麼這個解法成立？」 | 「為什麼鏈式推理能湧現？」 |
| *邊界* | 「它在什麼時候失效？」 | 「資料稀疏時這套辦法還成立嗎？」 |

混合的意義：

- 純動作問題 = 教程
- 純對比 = 辯論稿
- 純因果 = 論文
- 純邊界 = 反思

只有混合，才能復刻原作那種「方法 + 代價 + 限制」的真實張力。

## Q 的禁忌

- ❌ 「什麼是 X？」 —— 一句定義打發，沒承重
- ❌ 「X 有幾個步驟？」 —— 算不上問題，是問目錄
- ❌ 「X 重要嗎？」 —— 答案預設，沒張力
- ❌ 「我們應當如何看待 X？」 —— 學術腔，沒具體動作
- ❌ 「X 的優缺點是什麼？」 —— 商學院八股
- ❌ 「X 對未來意味著什麼？」 —— 沒法落地

## Q 的語氣

不要包裝。不要「那麼」「接下來讓我們討論」。直接砸：

| 重寫前 | 重寫後 |
|--------|--------|
| 我們應當如何看待 token 經濟性問題？ | 錢花在哪一步才划算？ |
| 在 AI 工程實踐中，並行處理是否合適？ | 並行海投錯在哪？ |
| 該方法的核心機制是什麼？ | 它憑什麼能 work？ |
| 這種方法有什麼侷限？ | 它在哪兒翻車？ |

口語 > 學術腔。20 字以內 > 長複合句。

## A 的四段

```
*結論*：（一句話——能脫離上下文被抄走）
*形式化*：（一行可視的文字關係式）
*怎麼想到的*：（2-4 條短句的論證步）
*邊界*：（什麼時候不成立 / 沒覆蓋什麼）
```

### 結論句的硬要求

一句話脫離上下文被抄走。讀者把這句話發給朋友，朋友讀完能 get 你說的什麼。

- ✓ 「深度比廣度貴，但只有深度能換洞察。」
- ✓ 「獎勵訊號會把模型鎖死在已會的軌跡裡。」
- ✗ 「總的來說，token 應該用得講究些。」
- ✗ 「該方法在多個維度上都展現了一定優勢。」

### 形式化的硬要求

用文字 + 簡單符號把思想壓成一行可視的關係。是"思想的幾何"，不是"數學的公式"。

允許符號：`= ≠ → ← + - × ÷ < > ⊃ ⊂ ⊥ ∧ ∨` + 中文 + ASCII。禁 LaTeX、禁複雜運算式。

四種常見模式：

| 模式 | 例 | 適用 |
|------|-----|------|
| *等式* | `通才 = 協調員；專才 = 幹活的` | 給概念分配角色 |
| *對比* | `舊: 大模型 = 全棧；新: 大模型 = 協調員` | 翻轉預設框架 |
| *流向* | `資料 → token → 答案 = 損失 + 浪費` | 揭露管道損耗 |
| *遞進* | `呼叫 → 介面 → 雙語熱線` | 追到根因 |

也可以是簡短公式或 ASCII 小圖（只用基礎字元，禁 Unicode 繪圖符）：

```
深 = 1 個 agent × 100 步 > 100 個 agent × 1 步
```

或：

```
廣: ── ── ── ── (淺嘗)
深: |
    v (鑽透)
```

形式化的檢驗：把它單獨抽出來給一個沒讀 A 的人看，他能不能 get 出大致意思？能 → 合格。需要解釋 → 重寫。

### 論證步的硬要求

每條短句只走一步推理。前一步必須開啟後一步的口子。

- ✓
  - 100 個 agent 各想 1 步，期望命中率 ≈ 1/50
  - 1 個 agent 想 100 步，每步前一次的輸出做下一次的輸入
  - 同樣的 token 總量，命中率不一樣

- ✗ 「在多 agent 協同的情景下，併發數量的增加並不必然帶來質量的提升，因為質量與思考深度密切相關，而思考深度需要時間序列上的迭代……」

  （一段話堆一起 = 沒拆開 = 不可追溯）

### 邊界的硬要求

誠實度測試。每個結論都有它不成立的地方。把它說出來。

- ✓ 「前提是任務目標穩定可被反覆驗證。開放式探索任務（比如『寫一首詩』）不一定要走深度路線。」
- ✓ 「對小模型不成立——小模型迭代收益遞減很快。」
- ✗ 「（不寫）」 —— 讓 A 看著像真理，實則脆弱
- ✗ 「未來工作可以探索更多維度。」 —— 公關辭令，不是邊界

邊界 ≠ 缺點。邊界是「條件」，缺點是「評價」。我們寫邊界。

## Q-A 鏈的拓撲

不是列表，是路徑。設計時先畫一張草圖：

```
Q1 ─┬─→ Q2 (在 Q1 答案上深入)
    └─→ Q3 (Q1 引出的對比)
Q2 ──→ Q4 (Q2 邊界提示的)
Q4 ──→ Q5 (收口反問)
```

讀者從 Q1 走到 Q5，相當於復刻了作者的推理路徑。

*亂排 = FAQ。有依賴 = 推理路徑*。

## 數量節制

5-10 個 Q 是甜區。

- < 5：覆蓋不全，讀者覺得沒吃飽
- > 10：讀者疲勞，張力散掉
- 7 ± 2 是最舒服的——能裝下作者的核心論證，又不囉嗦

如果原材料思想密度大（比如一本書一篇深論文），不要硬塞——分主題做多份 Q-A，每份 5-10 Q。

## 自檢清單

寫完整篇後，逐條過：

- [ ] 每個 Q 都能抗住「能不能一句定義打發」
- [ ] 每個 A 嚴格四段（結論 / 形式化 / 步驟 / 邊界）
- [ ] 結論句脫離上下文還能被抄走
- [ ] 形式化一行可視——單獨抽出來給沒讀 A 的人也能 get
- [ ] 論證步每條只走一步推理
- [ ] 邊界寫的是「不成立條件」，不是「未來工作」
- [ ] Q 鏈有方向感（刪一個後續會塌）
- [ ] Q 型別混合至少三類
- [ ] 沒有「什麼是 X」型 Q
- [ ] Q 句 ≤ 20 字
- [ ] 總數 5-10 Q
- [ ] 中文母語，無學術腔

任何一條不過 → 回去改。
