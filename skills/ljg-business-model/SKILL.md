# ljg-business-model

把使用者的資訊變成一張能看清「為誰創造什麼價值、如何交付、如何收支」的商業模式畫布。主產物為中文橫版 PNG；同時保留 HTML 和結構化 JSON，便於修改、追溯與重繪。

## Workflow Routing

| 輸入 | 處理與交付 |
|---|---|
| 專案介紹、訪談、文件、零散描述 | 依據下方合同整理，執行 `Tools/Render.ts`，驗證後交付畫布 |
| 現有畫布與補充材料 | 以新材料更新指定模型；保留未受影響的資訊，重新生成 |
| 多個獨立業務／商業模式 | 每個模式一張畫布；同一平臺的多邊客戶留在同張圖中並用 C1、C2 關聯 |

## 內容合同

- 開始前確認物件與範圍。只給公司名且沒有任何業務資料時，詢問業務描述或經使用者授權補充研究；資訊夠畫初稿就直接畫，缺項寫「待補充」。多個可能物件會改變畫布時，先問一個聚焦的問題。
- 讀取 [CanvasGuide.md](CanvasGuide.md) 校準九模組的定義、關係與經典佈局。用使用者材料為主體，不自動用行業常識補成事實。
- 每個要點標記 `given`（材料提供）、`inferred`（推測）或 `unknown`（待補充）。「材料提供」不等於外部驗證。`given` 關聯來源編號，`inferred` 附依據；使用者明確的計劃仍寫「擬／計劃」，不能改成正在發生。
- 每格優先放 2–4 條具體要點。保留客戶是誰、買什麼、誰付款、計價單位等區別資訊。儘量寫成「物件＋動作／結果」；收入留價格與週期，成本留驅動因素。沒有材料支援時不編金額、規模、合作方或結論。
- 九格放在同一畫面。保持經典空間關係，成本與收入位於底部；不畫等寬的 3×3 九宮格，不擅自換成 Lean Canvas。顏色服務於分割槽與客戶對應，推測同時用文字標籤，不能只靠顏色辨別。

## 生成與驗收

在唯一臨時目錄準備輸入 JSON，結構見 [Tools/Render.help.md](Tools/Render.help.md)，完整虛構示例見 [Example.json](Example.json)，版式參考見 [Example.png](Example.png)。將本技能真實目錄記為 `SKILL_DIR`，從任意工作目錄執行：

```sh
bun "$SKILL_DIR/Tools/Render.ts" --input "$WORK_DIR/model.json" --output "$WORK_DIR/model.html"
```

| 使用者意圖 | 引數或行為 |
|---|---|
| 預設畫卡片 | 預設寬度 1600 CSS px；最終匯出 PNG |
| 指定寬度 | `--width 1200` 至 `--width 2400`；仍需檢查可讀性 |
| 儲存到指定位置 | 驗收後把最終 PNG、HTML、JSON 放到該目錄 |

使用本機真實瀏覽器開啟 HTML，等待字型就緒，檢查九格順序、全部文本與溢位。當前環境有 Interceptor 時按其隔離與截圖合同執行；其他環境用可用的真實瀏覽器工具。`window.businessModelAudit()` 提供塊數、缺項、推測和幾何溢位檢查。匯出整個 `#canvas` 為 PNG，推薦 2 倍畫素；沒有截圖能力時保留 HTML 並明確 PNG 未完成，不能把 HTML 連結充作圖片。

開啟最終 PNG 看全圖，再放大密集區域檢查。若文字過密，先精簡重複表述或增高畫布；保留關鍵條件，禁止裁切、隱藏超出內容或縮字硬塞。渲染器拒絕過長／過多條目時，整理輸入後重跑，不繞過校驗。

最終在對話直接展示 PNG，給出 HTML 和 JSON 的檔案連結；簡短指出影響理解的待補充資訊。所有草稿與截圖留在臨時目錄，只有已驗收產物進入交付目錄。

## Gotchas

- 客戶細分是服務物件；付費方可能與使用者不同。多邊平臺需在價值、渠道、收入中保留對應關係。
- 渠道描述獲客、成交、交付路徑；客戶關係描述如何建立與維繫互動。資源是擁有／可呼叫的東西，業務是反覆做的事，夥伴是外部參與者。
- 收入來源是如何收費，融資不是收入；成本結構是支出邏輯，不能憑此推算利潤或把未標週期的資料相加。
- 歸類清楚不代表商業模式已成立。相互矛盾的材料、未驗證需求與缺失付費邏輯應留痕，不能用順滑的總結抹掉。
- 頁尾保留 Business Model Canvas、Strategyzer.com 與 CC BY-SA 3.0 歸屬；此處是中文改編排版，不是官方原版或對原書全文的複述。許可適用於畫布模板，使用者業務材料的權利不因此改變。

## Examples

- 「ljg-business-model：我們為小餐館提供採購服務，按成交額收費……」→ 用已有資料畫一張卡；缺失夥伴和成本寫待補充。
- 「把這份雙邊平臺訪談做成商業模式畫布」→ 使用者與付費方分別標記，追蹤各自價值和收入路徑。
- 「這是昨天的畫布，現在改為年費訂閱」→ 更新收費方式，並依據補充材料檢查客戶關係和成本是否也變化；無證據的變化標為推測。
