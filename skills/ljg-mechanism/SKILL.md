# ljg-mechanism · 機制研究

從眼前的現象中找出真正起作用的關係。生成解釋後，讓它與競爭解釋一起接受現實檢驗；根據證據修正物件、關係或成立條件，給出當前最紮實的機制判斷。

「solid」指關鍵關係有可檢查的依據、能夠區分競爭解釋、能推出新觀察，並留下修改自己的入口。完整、流暢或引用很多，均不足以達到這個標準；公開證據不足時，交付領先猜想和具體缺口。

## Workflow Routing

| 請求 | 執行 |
|---|---|
| 提供現象，希望解釋其生成過程並驗證 | 閱讀 [Workflows/DiscoverMechanism.md](Workflows/DiscoverMechanism.md) |
| 希望示範、學習或「走一遍」 | 使用同一研究框架，在成品中展開四個環節與判斷變化 |
| 補充新事實、反例或改變範圍 | 回到受影響的觀察或因果關係，更新判斷，不從頭重複無關部分 |

## 研究約定

- 原始現象也需要核對。保留有價值的觀察，明確物件、指標、比較基準和時段；「大家」「越來越」「沒有效果」等概括不能直接當全稱事實。
- 機制說清「誰或什麼，在什麼條件下，通過哪些中間變化，生成什麼結果」。「供求」「激勵」「文化」「系統」等名稱須展開到可觀察的過程。
- 保留能爭奪同一解釋物件的競爭解釋，寫出它們會產生的不同觀察。方向不同、時間不同、影響的人不同，也可以形成區別性預測。
- 預設使用當前可用的聯網搜尋與正文獲取能力，檢驗現象和機制。來源支援的範圍，與自己的推斷、教學設例和未知分開。
- 新材料可以推翻、重寫或收窄機制。聲明後的反例不能靠不斷追加例外消解；需要說明原預測為何失敗、新關係會推出什麼不同結果。

## 成品

預設中文，直接在對話中交付。先給機制判斷與證據強度，再以具體物件講清過程，展示最能改變判斷的競爭解釋、證據與邊界。四步是研究框架，不要求把全部檢索過程或思考過程打印出來。

涉及關鍵因果時，把來源連結放在對應判斷旁邊；說明來源實際支援的是現象、機制環節還是因果關係。正文應讓讀者看見：當前相信什麼、為什麼、什麼觀察會使它改口，以及換個現場時必須保留哪些條件。

使用者要求完整示範時，按「看反常 / 追過程 / 分解釋 / 帶條件遷移」展開。比較確有幫助時用短表，承重關係難以看清時用簡圖；不給每個簡單問題硬加圖、公式或固定數量的假說。

研究預設只讀，不自動建立筆記、報告檔案、日誌、規則或記憶。使用者另行要求儲存時，遵循指定位置與格式。聯網不可用或使用者要求離線時，說明只完成了推演，不能聲稱已聯網驗證。

## Gotchas

- 反常既包括「預期條件缺失，結果卻出現」，也包括「條件已出現，預期結果沒有出現」。普通現象也可以通過重新追問其生成過程成為研究物件。
- 產能、產出、合格交付、成交、收入、利潤與單位時間回報是不同指標；平均變化、個體變化和群體構成變化也要分開。
- 一個來源證明現象發生，不自動證明候選機制成立。把同一論文的多次轉述計作多個獨立證據，會誇大支援。
- 沒找到反例不等於通過驗證；未顯著不等於無效；缺少區分證據時可以同時保留多條解釋。
- 跨域類比可生成猜想，不能代替當前領域的證據。遷移時既要保留關係，也要檢查關鍵條件與失配處。
- 一個反例是否改變總體判斷，取決於原來的命題口徑。不能用一個贏家否定平均停滯，也不能用平均停滯否定個體獲益。

## Examples

- `/ljg-mechanism AI 讓創作容易了，為什麼收入沒有同步增長？`：拆開產能、交付、成交、價格與淨收益，比較需求瓶頸、競爭替代和中間環節提速等候選解釋，再檢索能區分它們的材料；不預設所有領域都由同一機制主導。
- `沒人統一指揮，為什麼群裡的問題仍能找到回答者？走一遍這個框架。`：對照成員自行認領與少數人集中撮合，找出關鍵參與者缺席時的不同預測；缺少該群的過程證據時，保留為待檢驗解釋。
- `網上都說某項技術沒有實際效果，幫我找機制並驗證。`：先核對「效果」的指標、時期和適用群體；原始概括不成立時，改寫研究問題，再解釋哪些環節改善、哪些環節仍然卡住。
