# ljg-analogy：讓關係在另一個場景裡顯形

使用者給出一個場景，交付一個讓人先看見畫面、再認出關係、最後對原場景多懂一點的類比。物件可以相距很遠，關係卻對得很近。新奇不能抵消失真；熟悉的物件也能承載出人意料的關係。

術語方向固定：**使用者想理解的場景是目標域；借來幫助理解的場景是基域。** 搜尋從目標域出發尋找基域，知識遷移從基域回到目標域。使用者用詞相反時按實際意圖工作，不為術語打斷創作。

## Workflow Routing

| 請求 | 處理 |
|------|------|
| 給一個場景，尋找類比或隱喻 | 按下文的成品標準交付一個主類比 |
| 比較兩個物件、產品或機制 | 用共同的關係框架，同時保留共同點與關鍵差異 |
| 指定受眾、領域、文風或只要一句 | 保留結構約束，服從使用者的呈現要求 |
| 要多個方案或比較已有候選 | 比較不同關係焦點，點出推薦項與取捨 |

## Gotchas

- 「都很複雜」「都是網路」「都需要平衡」適用面太寬，不能單獨支撐類比。關係要說清誰對誰做了什麼，哪些條件限制它，怎樣產生結果或形成佈局。
- 多個物件配對只是字典。優先保留受同一個因果、約束、比例或空間結構統轄的關係，不能以共同點數量充當系統性。
- 「更高階」指關係之間的關係，不等於更抽象、更宏大，也不限定為因果鏈。比例、空間和情感關係同樣可以承重。
- 一套對映中角色要穩定，不能為了下一句方便，讓同一物件偷偷換身份；確需比較不同側面時，明確換了一套對映。表面屬性不隨關係自動遷移。
- 基域是找來的，目標域事實是使用者給的。不能為了讓比方成立，替目標域補出動機、因果或結局；缺項只能作為明確的假設。
- 類比帶來候選推論，不能證明目標域必然如此。尤其不要從自然過程推出社會行為的必然性、正當性或某個人的意圖。

## 輸入是否夠用

至少能認出場景裡發生了什麼，以及使用者希望照亮的關係。只有一個詞而無可辨認情境時，問一個能改變類比選擇的問題；詞語有多種常見指向時，先確認它指什麼，問題中的選項也不能預設某一種含義。已有可用場景時直接工作。未指定受眾，預設面向普通中文讀者，優先選少解釋也能想像的生活場景。

類比對準讀者當前要完成的理解任務：辨認什麼、區分什麼，或預測哪種變化。用途、組成、運作方式與體驗是不同的解釋焦點；讀者問兩者怎樣不同，分別概括它們的用途可能答非所問。結合提問與已有上下文選焦點，必要時用一句「這裡著重看……」交代，不把這項檢查變成每次都向使用者補問。

使用者強調的目標、權力差異、時序和約束不能在抽象時被抹掉。版本與狀態也是物件身份的一部分：新證據改變角色、流程或依賴關係時，重新檢查取景與主類比。若原候選已不能保留承重關係，就換掉它，不能只在末尾補一句版本差異。

## 什麼樣的類比值得交付

**任務吻合。** 對映保留的是讀者這次需要理解的關係。一個比方能解釋物件的某個特點，仍可能與眼前的問題無關；關鍵看它能否改善當前的辨認、區分或理解。

**關係成立。** 兩邊都存在同一條有資訊量的關係骨架。讀者能把人物或物件逐一放回各自角色，核對作用方向、先後順序、依賴條件與反饋。允許只解釋區域性，但不能用一句泛泛的「只是類比」掩蓋承重關係相反。

**關係連得起來。** 有一組相互支援的對應，而非為了湊數收集的相似點。若一處改變會牽動另一處，說明這條依賴怎樣在兩邊重現。簡單的比例或空間對應已經足夠時，不必硬加因果或湊滿關係數量。

**畫面能獨立站住。** 基域裡有具體物件和動作，普通讀者不用先聽一遍新理論就能理解。可以用明確標為「設想」的構造場景；不能編自然機制、歷史事件或名人故事當事實。

**多照出一點。** 類比至少讓一項原先不顯眼的關係變得可見：盲點、約束、代價、後果或可區分兩種判斷的條件。這個增量要能從對映推出。驗收解釋性類比時，用一個未直接照抄原描述的小情境，檢查它能否幫助讀者辨認差異、推測結果或選擇下一步；只能複述名稱與特點的候選仍然偏弱。這是內部內容檢查，不必每次給使用者出題，也不等於讀者實測。文學隱喻可以改變讀者看待一種關係的方式，不強加操作性檢驗或科學實驗。

**候選經得起比較。** 當不同候選都能說通時，用同一個理解任務比較它們：誰保留了更關鍵的關係，誰能支援更具體的區分或推論，誰需要額外解釋得更少。只有喻體名詞不同、關係骨架相同，不算另一種結構。關係可信與受眾可理解是底線；熟悉的近域對應可以優於新奇的遠域對應，距離本身不計作質量。候選探索留在內部，使用者未要求時只交付最強方案；沒有合格候選就說明具體缺口。

**邊界具體。** 指出基域哪個醒目的特徵不能帶過來，或哪專案標域條件變化後，對應關係就會斷開。用與本次類比有關的一句話完成，避免通用免責宣告。

## 比較兩個物件時

優先在同一熟悉領域中找一組場景，用同一套角色與關係描述兩邊，使共同點保持可比、關鍵差異清楚顯現。分別給 A、B 找到貼切形象，仍不足以說明 A 與 B 怎樣不同；可借用的是一組有區別的運作關係。若跨兩個基域更準確，也應保留共同的比較依據，不強湊同域。

檢查兩種對應是否有區分力：交換喻體以後，如果不用改變承重關係仍能輕易圓回來，它們可能只命中了共同屬性。把一個新輸入或條件變化放進兩邊，讀者應能從類比看出各自怎樣處理、會出現什麼不同。若不同答案全靠另外補寫目標域事實，喻體本身就沒有提供足夠幫助。僅按原文換名詞，或把優劣標籤塞進比方，也不能替代這項檢查。

## 成品怎樣說

預設直接在對話交付，不自動建立筆記、圖片或檔案。通常用幾段話說透一個主類比，篇幅隨場景伸縮：

- **先給類比本身。** 用一句有畫面的中文，讓人立即知道拿什麼來比什麼。把真正承重的關係帶進這句話，避免空泛的「X 就像 Y」。
- **讓對應執行。** 把基域中的具體局面講明白，再接回使用者的場景。複雜對應可以用短表，表裡寫「關係怎樣對應」，不能只填名詞對名詞。
- **落回新增理解。** 說清這個比方讓原場景哪一點變得更清楚，以及最容易被誤帶過去的那一點。不要只換詞重述開頭。

以上是資訊要求，不是固定標題模板。使用者只要一句時，只交付一句；使用者要可直接引用的成稿時，先給乾淨成稿，不把驗收語言塞進正文。隱喻可以省去「像」，結構對應仍須成立。

## 理論與事實邊界

本技能借用 Gentner（1983）的關係對映與系統性原則。理解任務、雙物件對照、候選淘汰、受眾熟悉度、認知增量與具體邊界，是為創作任務增加的設計標準，不宣稱出自論文或已被論文驗證。

關於定義、非因果關係、隱喻與理論外推有疑問時，讀 [Theory.md](Theory.md)。維護或試跑時使用 [EvalCases.json](EvalCases.json)；這些用例只定義輸入和驗收依據，不規定唯一的正確比方。

日常構造場景不必聯網。最終類比若依賴某項不確定的科學、歷史或行業事實，先用當前可用檢索工具核對一手材料；核對不了，就換成事實可靠的基域，或明確限定為假設場景。

## Examples

- 「收藏了很多文章，真遇到問題卻找不出來，給個精妙類比。」成品應照亮存入與取用之間的關係，對映到具體情境，不能只用「知識寶庫」讚美數量。
- 「兩個工具都能完成任務，一個由我逐項開會話安排，另一個從主會話接收需求並分派、彙報。用類比講清區別。」成品要保留入口、分流與協調的差異；不把二者泛分成執行工具與資料容器，也不預設唯一的正確喻體。
- 「離家多年後，聽見一句鄉音就覺得有人在等我。只要一句隱喻。」成品保留聲音、歸屬與關係被喚起的結構，只給一句，不自動加表格或行動清單。
