# 共享影像生成協議

這份協議決定三種影像型 mode 怎樣從文本得到生成點陣圖。`-f` 預設不生成新圖，只在原稿自帶圖片時讀取來源保真條款；其他 mode 檔案只追加自己的視覺語法，不得複製或改寫這裡的共同合同。

## 一、先判定資產身份

每個視覺資產先歸入一類：

| 型別 | 含義 | 處理 |
|---|---|---|
| `generated` | 為這張卡新生成的概念場景或物件 | 進入本協議 |
| `source` | 原文照片、圖表、截圖或證據 | 本地快取，保真引用，標來源 |
| `brand` | 既有 logo 或頭像 | 原樣保留，不充當內容圖 |
| `structural` | 文字、數字、箭頭、軸線、標籤、分格 | 用 HTML/CSS 實現 |

不得把 `source` 重生成後說成原圖，也不得把 `structural` 交給圖片模型排版。

## 二、建立視覺母題表

寫提示詞前先完成表格；一行對應一個候選資產：

| asset_id | 源判斷 | 核心衝突或變化 | 視覺動詞 | 承載物 | 語義工作 | 類比對應（可空） | 影像角色 | 比例 | 文字安全區 | 色彩/媒介 | alt |
|---|---|---|---|---|---|---|---|---|---|---|---|
| `g01` | 一句可核對的判斷 | 哪個條件使結果不同 | 切開/拉扯/翻轉/聚攏 | 具體人物或物件 | 例項/機制動作/條件對比/類比 | 用類比時說明對應關係與失效處 | hero/scene/detail/vignette | 4:3 等 | left/right/top/none | mode 規定 | 具體動作及意義 |

母題表必須滿足：

1. 「視覺動詞」能被拍到或畫到；避免「體現、象徵、賦能」。
2. 「承載物」是具體的人、手、門、繩、容器、地形或機器，不是抽象概念名。
3. 不強制構造隱喻；能呈現任務物件時優先呈現物件。類比不冒充例項、事實或實證；同一案例可連續變化，不追加沒有新資訊的同義畫面。
4. 安全區由後續文字佈局決定；沒有文字覆蓋就寫 `none`。
5. 資產數量由敘事需要決定，不能為填空而新增。

知識講解中，畫面應讓判別特徵、關鍵條件或結果變化可見；只有具體承載物，沒有它與源概念的對應，仍不足以形成下層材料。文字可以補清對應關係，不讓讀者自行猜隱喻。

## 三、建立系列聖經

有兩幅以上生成圖時，先鎖定系列聖經：

- 媒介：線描、木刻、新聞插畫、拼貼、攝影等，只選一種主媒介。
- 線條與材質：粗細、顆粒、紙面、網點或光線邏輯。
- 角色與物件：年齡、髮型、服裝、比例、關鍵道具、左右手等連續特徵。
- 鏡頭：視平線、焦段感、景別範圍、是否允許俯拍或極端透視。
- 色彩：背景色、墨色和最多兩種強調色。
- 構圖：系列共同的留白方向與主體佔比。

同系列可以換隱喻與動作，不能每張換一套世界觀。

## 四、提示詞骨架

按以下順序寫正向提示詞：

```text
[輸出型別與媒介]。
Scene: [可見場景、主體、關鍵動作、衝突結果]。
Composition: [比例、主體位置、景別、視覺焦點、文字安全區]。
Series style: [系列聖經中的線條、材質、色彩、角色連續性]。
Semantic role: [它對應哪條源判斷；若為知識講解，讀者依據哪個可見特徵判別、什麼條件改變結果]。
Background: [transparent 或 mode 指定的純色平底]。
No readable text inside the image.
```

提示詞先寫具體場景，再寫風格；不要用一串風格形容詞代替畫面。若要求透明背景但工具不穩定，使用與模板完全一致的純色平底，並在資產記錄中註明。

## 五、統一負向約束

每次生成都附加：

```text
no readable text, no letters, no numbers, no logo, no watermark,
no captions, no labels, no speech bubbles, no interface panels,
no generic AI brain, no robot mascot, no decorative stock illustration,
no gradient, no glow, no glossy 3D, no heavy drop shadow,
no unintended extra limbs or objects, no cropped key subject
```

mode 檔案可以追加專屬負向約束，但不能刪除這些共同項。

## 六、先樣圖，後批次

1. 從母題表選最能代表系列的 `g01`。
2. 只生成這一張，檢查語義、構圖、安全區、角色、背景、無字和色彩。
3. 只改一個失敗變數後重生；不要同時換隱喻、鏡頭和風格。
4. 樣圖通過後，鎖定系列聖經，再生成其他資產。
5. 每個失敗資產最多兩次定向重生；仍失敗則停止該 mode 的交付。

## 七、呼叫影像生成工具

- 使用當前執行時可用的 image generation 工具實際生成圖片；禁止用 HTML/CSS、圖示或遠端相簿假裝完成了主視覺。
- 新圖從母題表的一行構造一次完整 prompt。不要把整篇文章原樣扔給圖片模型，讓它自行猜畫面。
- 工具支援參考圖時，只把已經通過校準的系列樣圖用於角色/媒介連續性；不能把原文證據圖改造後冒充原圖。
- 每次呼叫只改變母題表中明確的失敗變數，並把結果對應回唯一 `asset_id`。
- 工具返回臨時資產後，立即儲存到當前卡片的本地工作目錄；未落盤的返回值不算完成。

## 八、落盤與資產記錄

生成圖必須先儲存為本地 `.png` 或 `.jpg`，再進入 HTML。穩定命名：

```text
{name}-{mode}-{asset_id}-{role}.png
```

在工作記錄中保留：資產 ID、角色、提示詞摘要、尺寸、檔案路徑、SHA-256、來源型別。兩種不同角色不得複用同一雜湊。禁止遠端生成圖 URL、隨機相簿和臨時佔位圖進入成品。

寫 HTML 前逐一確認：

- 檔案存在且非空；
- 畫素尺寸與母題表比例一致；
- 主體沒有被裁掉，安全區方向正確；
- 沒有可讀或偽造文字、Logo、水印；
- `alt` 非空，描述可見動作與語義，不寫風格讚美。

## 九、HTML 整合

所有圖片使用本地路徑：

```html
<figure class="generated-art generated-art--ROLE" data-asset-id="g01">
  <img src="/absolute/local/path.png" alt="一隻手把兩股相反方向的繩索拉回同一支點">
  <figcaption>由 HTML 寫準確說明；圖片本身不排字。</figcaption>
</figure>
```

- 主圖可用 `object-fit: cover`，但關鍵主體必須落在安全區內；概念物件優先 `contain`。
- 模板頂層槽無圖時使用 `data-state="empty"` 並替換 `src` 與 `alt` 佔位符為空；CSS 必須隱藏整個 `figure`，不顯示破圖圖示。
- 標題、來源、數值、公式、座標、箭頭、批註和對話泡統一由 HTML/CSS 疊加。

## 十、驗收與失敗合同

截圖前等待 `document.fonts.ready`，再確認每個 `img` 都滿足 `complete && naturalWidth > 0`。任一圖片失敗就不截圖。

最終檢查：

1. 資產數量與當前 mode 的預算一致。
2. 每圖能回指母題表中的一條源判斷。
3. 同一輪講解的角色、物件、媒介和色彩連續；換案檢驗可更換物件，畫面不能重複同一資訊。
4. OCR 或人工檢查沒有可讀/偽文字。
5. HTML 中無未替換佔位符，所有 `alt` 有意義。
6. PNG 的修改時間晚於 HTML 與所有生成圖資產。
7. 整圖與分段畫素檢查均通過後才交付。
