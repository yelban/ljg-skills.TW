# 模具：漫畫（-c）

把內容鑄成黑白漫畫分鏡。生成點陣圖負責讓角色、場景、動作與結果可見；HTML/CSS 負責把概念名、對白、旁白、音效字、證據分寸與來源寫準確。

## 1. 先把解釋變成認知因果拍點

Read `references/image-generation.md` 與 `assets/comic_template.html`。確認標題、作者、來源與事實邊界；輸入若是已驗收 Org，先鎖定路徑與 SHA-256，制卡完成後確認原始檔未變。

先找一個能承載核心機制的最小可執行案例。它必須讓讀者看見輸入、動作和結果；刪掉關鍵反饋、時序或約束會改變結論時，那一項必須保留。優先讓同一角色、道具與空間貫穿全篇，因為漫畫的理解力來自前後可比較，不來自每格換一個漂亮隱喻。

分鏡按下面的因果引擎生長：

```text
最小案例 -> 零號模型執行 -> 一個可觀察缺口
         -> 一個概念補位 -> 同案重跑 -> 下一個缺口
         -> 完整模型重跑 -> 遷移或失效邊界
```

每一步都要改變讀者此刻能解釋的東西：

1. **最小案例**：建立具體處境，讓目標和約束進入畫面。
2. **零號模型**：讓讀者最自然的舊解釋或舊做法真的行動一次。
3. **可觀察缺口**：用失敗結果、錯誤預測、混淆或代價證明當前模型不夠。
4. **單概念補位**：只引入解決當前缺口的一件東西，讓它成為動作、選擇或結構變化。
5. **同案重跑**：回到相同任務，畫出加入它以後最先改變的結果。
6. **繼續或停下**：仍有承重缺口才進入下一輪；當前模型已經夠用就停止加概念。
7. **整體回收**：從最初輸入重新跑完整機制，讓沿途零件接回同一臺機器。
8. **邊界拍點**：必要時改變一個條件，畫出模型遷移成功或首先失效之處。

格數不設固定範圍。短內容可以合併不承重的鋪墊，長文、論文或整本書則從完整因果主線選擇拍點；刪除某格後若讀者仍能完成同樣的認知跳躍，這格就是裝飾，應合併或刪除。不能繼承舊五格、六格或任意模板格數，再把內容硬塞進去。

每個分格只承擔一個可見動作或一個可比較結果。概念先以動作顯示必要性，術語在下一處 HTML 旁白、對白或標題中命名；不要第一格就端出完整答案，再用後續畫面複述它。

強耦合、併發或機率湧現的機制不能偽造成單線升級。使用並排分格、同一時刻的雙視角或狀態對照，讓幾股力同時顯形；讀者仍應看見「少了其中一股會先改變什麼」。

## 2. 漫畫系列聖經

批次生成前鎖定四類連續性：

1. **角色設定**：年齡、臉型、髮型、服裝、身高差、關鍵道具、左右手。
2. **線條與網點**：線寬、墨塊比例、網點顆粒、背景簡繁。
3. **鏡頭語法**：主景別、視平線、允許的透視強度、反應鏡頭規則。
4. **黑白關係**：紙白、墨黑、灰階數量與高對比出現的時機。

不要指定模模擬實漫畫家。按內容選擇描述性風格族：

| 風格族 | 適合內容 | 視覺特徵 |
|---|---|---|
| 精密機械線稿 | 技術、系統、裝置 | 清楚結構、細線、剋制網點 |
| 墨韻留白 | 哲學、內省、歷史 | 大留白、毛筆感、安靜景別 |
| 高對比暗黑 | 風險、權力、困境 | 大墨塊、硬光、壓迫構圖 |
| 粗線動勢 | 衝突、行動、速度 | 粗線、誇張透視、強運動方向 |
| 靜謐電影線描 | 人物、關係、日常 | 中遠景、環境敘事、低密度網點 |

## 3. 分格因果表

生成前先寫分格因果表。所有漫畫主畫面都必須是本地生成點陣圖；重要拍點可加 detail/reaction，但它必須幫助讀者看見當前動作或結果，不能只調節氣氛。

| panel_id | cognitive role | reader knows before | visible action | observable result | gap / new relation | continuity anchors | ratio | safe zone |
|---|---|---|---|---|---|---|---|---|
| `p01` | 最小案例 | 只知道目標 | 角色按直覺開始任務 | 舊模型開始執行 | 尚未命名 | 服裝、道具、空間 | 16:9 | top |
| `p02` | 可觀察缺口 | 相信舊模型夠用 | 動作撞上約束 | 結果偏離預期 | 當前缺口 | 同角色、同任務 | 4:3 | left |
| `p03` | 概念補位 | 已感到缺東西 | 角色加入一個新區分 | 第一處結果改變 | 新關係，術語後置 | 同道具、同機位 | 1:1 | right |
| `p04` | 同案重跑 | 理解新關係 | 相同任務重新執行 | 前後差異可比較 | 是否仍有缺口 | 同角色、同空間 | 16:9 | top |

表中每格必須通過三問：

1. 去掉它，讀者是否會失去一次必要的認知變化？
2. 它與前後格是否共享足夠的角色、動作或結果，可以直接比較？
3. 圖片中的動作能否獨立成立，而不是全靠旁白聲稱「這裡發生了變化」？

任何一問為否，先重寫拍點，不進入圖片生成。

## 4. 分格影像生成

提示詞追加：

```text
black-and-white manga panel art, clean paper background, coherent recurring character,
single readable action, visible cause-and-effect result, intentional camera angle,
controlled screentone and ink mass
```

專屬負向約束：圖片內不要對白泡、格線、旁白框、音效字、頁碼和彩色元素；不要照片感、光滑 3D 或多餘角色。關鍵主體需完整，方便 CSS 裁切。

先生成最能校準角色、空間和核心動作的代表格，不必機械選擇 `p01`。樣圖通過後再生成餘格；每次都把角色錨點、當前動作、可觀察結果和安全區寫回提示詞，不能只寫「same character」。

逐格檢查：讀者只看點陣圖，應能指出誰做了什麼、什麼結果變了；但概念名、結論、數字和證據等級仍留給 HTML。生成圖若把術語、介面標籤或對白直接畫進圖片，定向重生。

## 5. 來源分流

- 原文照片、截圖或圖表屬於 `source`，保真放入獨立證據格並標來源。
- 新漫畫畫面屬於 `generated`，不能寫成「原圖」或暗示出自原作者。
- 品牌 logo 只在 footer。
- 同一格不得把來源圖與生成圖無說明地拼成偽證據。
- 案例讓機制可見，不提供普遍性證明；事實主張與論文結論只推進到相鄰來源證據允許的位置。

## 6. HTML/CSS 分工

圖片寫法：

```html
<figure class="generated-art generated-art--panel panel-wide" data-panel-id="p01">
  <img src="/absolute/path.png" alt="主人公按原辦法推動機器，齒輪在第二個介面處卡住">
</figure>
```

用 HTML/CSS 疊加：

- `.panel` 格線與不等寬網格
- `.bubble` 對白泡與尾巴
- `.narration` 旁白框
- `.sfx` 音效字
- `.caption` 來源或時間

旁白和對白只承擔三種工作：點明讀者剛看見的缺口、在必要性出現後給概念命名、校準證據與邊界。若文字必須替畫面解釋「誰做了什麼、結果如何變化」，說明動作格還沒有設計完成。

圖片 `object-fit` 可以是 `cover`，但眼睛、手、關鍵道具和衝突點必須留在安全區。不同寬高比逐格決定 `cover` 或 `contain`；不能把一個裁切規則無檢查地套給所有分格。

頂部圖片槽使用 `.generated-visual--comic`，可作為封面 hero；不用時設為空。將版式 CSS 寫入 `{{CUSTOM_CSS}}`，分格寫入 `{{CONTENT_HTML}}`，替換 `{{LOGO}}`、`{{SOURCE_LINE}}` 與圖片槽。寫入 `/tmp/ljg_cast_comic_{name}.html`。

## 7. 截圖

```bash
bun assets/capture.ts /tmp/ljg_cast_comic_{name}.html ~/Downloads/{name}.png 1080 1500 fullpage
```

## 8. 自檢

- [ ] 格數來自認知因果拍點，沒有繼承固定格數或為版面湊格
- [ ] 最小案例、零號模型、可觀察缺口、單概念補位、同案重跑與整體回收均可定位
- [ ] 每個新概念都由前一格的缺口拉入，術語晚於必要性出現
- [ ] 每個分格只有一個可見動作或一個可比較結果，順序能脫離解釋讀懂
- [ ] 強耦合機制若存在，使用並排關係而非虛假線性順序
- [ ] 長內容覆蓋完整因果主線；刪除測試沒有發現裝飾格或缺失承重拍點
- [ ] 所有漫畫主畫面來自生成點陣圖；無空格、佔位格或重複雜湊
- [ ] 角色設定、線條、鏡頭、空間、道具和網點風格在全篇連續
- [ ] 格線、對白、旁白、術語、音效與來源全部由 HTML/CSS 承擔
- [ ] 圖中無可讀文字、泡框、格線、Logo、水印或彩色汙染
- [ ] 來源原圖與生成圖標註清楚，主張沒有越過來源證據
- [ ] 每個生成資產在進入 HTML 前都做過原尺寸視覺檢查
- [ ] 所有分格經過 DOM class-sweep；關鍵臉、手、道具和動作沒有被裁掉
- [ ] PNG 寬 1080，整圖與覆蓋全部高度的重疊分段檢查通過
