# ljg-card：鑄

內容進去，PNG 出來。生成圖負責把思想變成可見動作，HTML 負責把話說準確；`-f` 只設計原文的呈現，不改動原文，也不生成新圖。

`-l`、`-w` 承擔知識講解時，還要接通「具體情形 → 判別依據 → 有條件的關係 → 具體結果」。讀者應能從正文裡的動作或狀態看出物件憑什麼屬於某個概念，再用關係推出眼前的結果；只把例子放在術語旁邊，連線仍然缺失。先確定目標讀者要完成什麼判斷，再決定材料和畫面；下上結構不規定版面上下，也不要求每張卡從故事開頭。文學、敘事與審美表達按自身目的組織，不強加習題。

成品在內容自身的結論、問題或餘韻處結束，之後只留署名與來源。不要追加「閱讀邊界」、免責宣告、製作說明或驗收說明，也不要換個標題保留這類尾註。會改變理解的原文條件、分歧與限制，就近融入相應論證；提煉範圍、材料缺口和驗證狀態放在交付回覆中。`-f` 原稿已有的段落仍按全文保真合同保留。

## 引數

| 引數 | 模具 | 尺寸 | 影像角色 |
|---|---|---|---|
| `-l`（預設） | 長圖 · 靜線敘事 | 1080 × auto | 0–3 幅；有理解增益時用 1 個安靜主場景，必要時追加連續視覺拍點 |
| `-f` | 全文 · 原文排版 | 1080 × auto | 生成圖固定為 0；只保真呈現原稿自帶圖片 |
| `-c` | 漫畫 | 1080 × auto | 缺口驅動、同案重跑的漫畫分鏡 |
| `-w` | 白板 · 縱向論證 | 1080 × auto | 嵌入承重推理節點的區域性手繪動作；不設頂部主視覺 |

未給引數時使用 `-l`。

## 必讀順序

`-l`、`-c`、`-w` 每次執行都必須依次 Read：

1. `references/taste.md`
2. `references/image-generation.md`
3. 當前 mode 檔案
4. 當前 HTML 模板

不得跳過共享影像協議直接寫提示詞，也不得把一種 mode 的影像語法套給另一種。

`-l`、`-w` 用於知識講解時，在第 3 步後、讀取模板前補讀 `references/learning-design.md`：其中包含讀者任務、下上連線、來源邊界、換案檢驗，以及四組失敗與修復對照。`-f` 不進入這條路線。

`-f` 依次 Read：

1. `references/taste.md`
2. `references/mode-full.md`
3. `assets/full_template.html`

`-f` 不生成新圖；只有原稿自帶圖片時才補讀 `references/image-generation.md` 的資產身份、來源保真與本地落盤合同。

## `-f` 字型優先順序

`-f` 的所有編輯性文字優先使用本機已安裝的 `KingHwa_OldSong`，包括 title、headline、章節標題、正文、強調、圖注、表頭與署名，從而保持整張長卡的字型氣質統一。瀏覽器檢測不到時，正文回退到 `Songti SC`、`STSong`、`Noto Serif CJK SC` 與 `serif`，標題類文字回退到 `PingFang SC`、`Hiragino Sans GB`、`Microsoft YaHei` 與系統 sans。不得為了制卡聯網下載、臨時安裝或遠端引用該字型。`code`、`pre` 與來源行保留等寬字型，因為字元對齊在這些位置承擔語義。

## `-f` 長文閱讀面

`-f` 通常產生超長卡片，因此使用獨立於 `-l` 的白底黑字閱讀面：畫布固定為純白 `#FFFFFF`，普通正文使用深中性黑 `#171717`，輔助資訊只用剋制的中性灰。1080px 成品的普通正文不小於 40px，行高保持 1.9，正文有效寬度約 896px；段距預設 36px，章節間距明顯大於段落間距。列表與引用同為 40px/1.9，表格 34px，腳註與程式碼塊 32px，圖注 30px。以約 390px 手機顯示寬度複查，正文約等效 14.4px；允許長圖增高，不為壓縮高度縮字。不得把暖紙底、小號網頁正文、過緊行距或大面積彩色模組帶入 `-f`。

## 全域性臨時目錄約束

無論從哪個目錄啟動，制卡前都必須在 `/tmp` 下建立本任務獨佔的臨時目錄。生成圖候選稿、用於組版的源圖、HTML、CSS、向量草稿、渲染輸入、截圖草稿、QA 切片、快取與日誌等所有中間產物，全部只能寫入該目錄。

只有使用者明確要求交付的最終檔案可以寫入 `/tmp` 之外。候選 PNG 和未通過驗收的渲染結果仍屬於中間產物。完成前檢查當前目錄和倉庫沒有遺留中間檔案，最終交付物驗收後清理本任務的臨時目錄。

## 共同生產線

1. 讀取 URL、貼上文本或本地檔案，確認標題、作者、來源與事實邊界。
2. `-f` 鎖定來源、建立有序原文塊賬本，直接進入 `references/mode-full.md`；不經過提煉、視覺母題或圖片生成。
3. `-l`、`-w` 的知識講解先按 `references/learning-design.md` 明確讀者任務，整理具體情形、判別依據、關係、結果與適用條件。進入版式前，實際草稿應把物件、動作或狀態、條件怎樣通向結果寫出來；源文缺少的材料記入製作記錄，交付時簡報。`-l`、`-c` 隨後建立視覺母題表；`-w` 先把此次輸入儲存為精確來源快照，再執行 `assets/prepare-whiteboard-source.ts` 建立逐段來源清單，讓論證賬本覆蓋這份獨立清單，並同時檢查論證承重與學習承重，才決定哪些步驟需要視覺化。不能從一句摘要直接進入版式。`-w` 的生成圖預算為 0–4 幅。
4. `-c` 呼叫當前環境的 image generation 工具，先生成一張代表圖校準語義與系列風格；`-l`、`-w` 的資產預算大於 0 時才做同樣校準，0 幅是合法結果。
5. 將圖片儲存為本地 PNG/JPG，逐一核對檔案、尺寸、構圖、無字與來源屬性。
6. 將所有可讀文字、數字、公式、標籤、箭頭和來源放入 HTML/CSS；圖片承擔具體場景、機制動作、條件對比或明確標明的類比。畫面有具體物件，不自動說明它提供了可用於判別的下層材料。
7. 讀取對應模板，替換全部佔位符。`-l`、`-c` 的頂部圖槽無圖時必須顯式設為 `data-state="empty"`；有圖時必須提供本地路徑和語義化 `alt`。`-w` 沒有頂部圖槽：把最終論證賬本寫入 `{{LOGIC_LEDGER_JSON}}`，每幅生成圖只在對應步驟內部出現，並用 `data-source-claim` 回指該步驟 ID。
8. 截圖前等待字型與全部圖片載入成功；任一圖片損壞就停止。
9. 交付前檢查整圖；長圖再用重疊切片覆蓋全部高度。
10. 知識講解另做內容審閱：關鍵概念有可用的判別依據，關係與例項對應，換案能暴露條件差異。來源與渲染檢查、內容審閱、讀者實測在交付回覆中分別報告，不排進卡片；提供試用題不能證明讀者已經學會。

`-l`、`-c`、`-w` 已判定為必要的關鍵生成圖失敗時最多做兩次定向重生。仍失敗就說明阻斷原因，不得改用遠端佔位圖、偽圖示或向量圖悄悄兜底；不能把失敗圖悄悄改寫成「本來就不需要圖」。

## 輸入與命名

- URL：用當前可用的網頁讀取工具獲取正文，並儲存明確來源。
- 貼上文本：直接使用，不補寫原文沒有的事實。
- 檔案路徑：Read 本地檔案。
- `{name}`：從標題或核心判斷提取，中文可保留，去標點，最多 20 個字元。

## 截圖工具

從 skill 根目錄執行：

```bash
bun assets/capture.ts <html> <png> <width> <height> [fullpage]
```

`-w` 截圖前必須先從精確來源快照生成獨立清單，並把二者一起交給截圖門禁：

```bash
bun assets/prepare-whiteboard-source.ts /tmp/<task>/source.txt /tmp/<task>/whiteboard-source-inventory.json
bun assets/capture.ts <html> <png> 1080 1600 fullpage /tmp/<task>/whiteboard-source-inventory.json /tmp/<task>/source.txt
```

來源清單必須直接由本次輸入生成，不能由論證賬本反推；否則賬本漏掉的段落也會一起消失，完整性校驗失去意義。

依賴缺失時：

```bash
bun install
bunx playwright install chromium
```

截圖指令碼會等待字型與本地圖片。不要繞過它的載入門禁。

## Gotchas

- 「具體例子 + 抽象結論」仍可能難讀。概念連線看正文是否寫出同一情形的歸類依據與結果變化；不能以例子、術語或驗收欄位都出現了代替內容審閱。使用者反饋難懂時，重建這條連線，再調整措辭；對照見 `references/learning-design.md`。
- `-l` 的識別度來自「極簡單線氣質 + 漫畫式可見變化 + 編輯式證據結構」。只做一張漂亮單幅會丟掉講解，只做連續漫畫會壓過長文；具體路由以 `references/mode-long.md` 為準。
- `-f` 的強調只能提升原稿中已經存在的字句：可以改變字號、字重、顏色、留白與語義標籤，不能抽出一句再複製成金句，不能補寫標題、導語、小結或過渡句。
- `-f` 的全文驗收看有序文本塊賬本，不看肉眼印象。改單字、調序、漏塊或重複塊都必須讓 `assets/verify-full-text.ts` 失敗。
- `-f` 不能因為 `KingHwa_OldSong` 缺失而阻斷，也不能悄悄改用遠端字型；缺失時由本地預設字型棧自然接管。安裝時則應在截圖前分別確認普通正文、title 與 headline 都實際解析到 `KingHwa_OldSong`，不能只看 CSS 宣告。程式碼與來源行的等寬字型是唯一例外。
- `-f` 的白底黑字是長文可讀性合同，不是臨時配色：背景必須是 `#FFFFFF`，普通正文必須是深中性黑，正文尺寸/行高不得低於 40px/1.9。暗硃紅只標記少量分隔和強調，不能與黑字爭奪主體。
- 稀疏線稿在區域性裁圖裡清楚，放回整張長卡可能完全消失。`-l` 的代表圖必須同時通過區域性畫素檢查和整卡縮略檢查；必要時只加粗輪廓，不連帶更換隱喻、鏡頭或構圖。
- `-c` 的格數由認知因果拍點決定，不設固定範圍。短內容不湊格，長內容不因模板刪掉承重關係。
- 漫畫主畫面負責讓動作與結果可見；概念名、對白、旁白和證據分寸仍由 HTML/CSS 寫準，不能讓圖片模型代寫解釋。
- 同一輪講解或同案重跑要求角色、道具與空間連續；換案檢驗可以更換物件，保留待檢驗關係。每個講解拍點換一套隱喻會切斷前後比較。
- `object-fit: cover` 可能只裁壞一格。逐資產檢查後仍要掃描所有分格的臉、手、關鍵道具與動作點，再檢查最終 DOM、整圖和重疊切片。
- `-w` 的母結構不是五選一 topology，而是一條從問題沿推理展開的 `.reasoning-spine`。chain、branch、timeline、matrix、radial 是可以嵌入主幹的區域性結構；真實文章允許先遞進、再分叉、再匯合，不能為了選一種圖形而刪除推理，也不必為收尾另造邊界節點。
- `-w` 在任何視覺決策之前建立論證賬本：每個源章節必須對映到步驟，或登記具體省略理由；每個步驟與關係都繫結賬本 ID。例子即使不參與證明，也可能承擔辨認概念的工作。來源對賬與賬本、DOM 一致是結構門禁，不能證明判別依據充分。
- `-w` 的主幹不斷，不等於每一層都要出聲。普通延續、解釋與遞進使用靜默關係；只有矛盾、問題改寫、分支、回收或邊界真正改變閱讀方向時，才顯示一條完整過渡句。不要用「繼續追問」「再向前一步」之類旁白替代原文中的具體未解壓力。
- `-w` 的生成圖不得成為正文之前的 hero。影像只嵌入它所解釋的步驟；刪圖後若論證、物件判別與結果理解都不受損，0 幅是正確結果。文字也可以提供完整下層材料。
- `-w` 的靜默關係只在賬本和真實 `.logic-relation` DOM 中保留端點，不顯示箭頭或文案；可見轉折的箭頭不能用 `::before`/`::after`，必須使用 `.relation-stem` 與 `.relation-arrowhead` 真實元素，並用唯一的 `.transition-sentence` 承擔整句過渡。
- `-w` 不聯網取字型。拉丁手寫字型不會提供中文字形，中文最終會無聲回退；模板使用本地楷體/中文 Sans 字棧，字型差異不得改變節點層級或幾何驗收。

## Examples

**Example 1：把論文或書鑄成長圖**

```text
User: 「把這篇論文做成卡片 -l」
→ 用一個穩定人物或物件承載可見變化：論文走「問題→機制→證據→邊界→決策」，書走「原狀→壓力→變化→餘波」
→ 知識講解先明確讀者任務，展示物件憑什麼歸入概念、關係怎樣落回結果；生成圖畫可見動作，準確文字由 HTML/CSS 承擔
→ 交付一張具有暖紙、稀疏黑線、單一暗紅與完整閱讀層級的 1080px PNG
```

**Example 2：把技術概念鑄成漫畫**

```text
User: 「把這篇技術解釋做成漫畫 -c」
→ 固定一個最小案例，讓零號模型先執行並暴露失敗
→ 每次只用一格引入當前缺口需要的概念，再回到同案重跑
→ 最後從頭執行完整模型，並留一個邊界拍點
```

**Example 3：把完整長文鑄成漫畫**

```text
User: 「把這份已驗收的完整筆記做成漫畫 -c，不限格數」
→ 先鎖定 Org 路徑與 SHA-256，再從全文因果主線選擇認知拍點
→ 格數服從承重關係與刪除測試，不繼承舊五格或固定頁數
→ 生成分格、組裝 HTML，完成逐圖、整圖與重疊切片 QA
```

**Example 4：原文一字不改地排成長圖**

```text
User: 「這篇文稿用 -f 鑄成全文卡片，原文不要動」
→ 鎖定來源與 SHA-256，把標題、段落、列表、引用、強調和腳註登記為有序原文塊
→ 不摘要、不補標題、不抽取重複金句；只用白底、深黑、KingHwa_OldSong、剋制灰階、字型層級與留白做編輯設計
→ 全文校驗器通過後截圖，交付一張生成圖數量為 0 的 1080px 原文長 PNG
```

## 交付合同

最終回覆至少報告：PNG 絕對路徑、畫素尺寸、內容來源、使用的 mode、生成圖數量，以及整圖/分段視覺 QA 結果。若輸入來自已驗收 Org，先記錄其路徑與 SHA-256，制卡後再確認原始檔雜湊未變。`-f` 還必須報告有序原文塊數量與全文校驗結果；生成圖數量固定為 0。

知識講解在交付回覆中額外簡報下上連線的內容審閱結果、未補齊的材料缺口，以及是否做過讀者換案實測。沒有實測時寫「未做讀者實測」，不以自審或程式通過代替學習效果。這些是交付資訊，不是成品正文或尾註。

## 維護自檢

升級模板或 mode 後執行：

```bash
bun run audit
bun test
bun run fixtures
```
