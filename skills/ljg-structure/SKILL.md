# 母題結構風洞

輸入一段資訊，穿過表象找到它反覆上演的母題，再把真正起作用的幾根結構畫清楚，送進風洞校準。預設結果要輕：讀者帶走一個說得明白的母題、一張能執行的關係圖、一個既能遷移又會改口的結論。

## 四個概念，不能混

- **主題**：資訊在談什麼物件，如「團隊討論」「AI 注意力」。它只圈定語義範圍。
- **母題**：不同領域反覆遭遇的同一類根本困境。它不是把原題換成更大的抽象詞，而是用更普通的話保留那條可遷移的關係。
- **類比**：兩個案例看起來相像，如「團隊像陪審團」。它只是發現入口。
- **結構**：刪掉領域名詞後仍成立的因果骨架。它說明什麼關係會生成什麼結果。

一句話：主題是名字，母題是難題，類比是線索，結構是因果機器。

## 理解契約

結構分析不是讓讀者記住一組抽象名詞，而是讓他能在心裡把關係跑一遍。完成的解讀必須做到：

- **概念明確**：每個承重概念都能用普通話說明「這裡具體指什麼」，並給出一個可見標誌。
- **關係明確**：讀者能複述「在什麼條件下，誰怎樣影響誰，先出現什麼變化，最後得到什麼結果」。
- **示例承載關係**：例子不只讓人覺得相似；其中的角色、作用方向和結果都能對應抽象關係。
- **邊界可以判斷**：條件變化時，讀者能預判關係會怎樣變化，也知道什麼觀察會迫使自己修改判斷。

案例負責讓模型執行，不負責證明模型普遍為真；風洞負責在內部改變條件、尋找邊界和校準判斷，最終只把有資訊量的試壓結果交給結論。

### 風洞如何進入結論

- **風洞是內部方法**：沿用同一個示例，改變一個關鍵條件，觀察預測怎樣變化，並找出模型何時失效、什麼訊號會讓判斷改口。它不再單列為可見章節。
- **結論是校準後的交付物**：先呈現同一示例在條件變化後的關鍵差異，給讀者具體抓手；再把差異壓成一條可遷移的抽象規則，回到原現象說明現在應該看見什麼。

風洞的完整推演留在內部，結論只帶出最能區分模型的條件變化、邊界或改口訊號。它們與抽象規則必須形成遞進，而不是把同一因果鏈說兩遍。

## 適用邊界

適合：問題機制不明、現成方案貧乏、多個現象彼此牽動，或需要超出普通 AB 測試的探索。

不適合：純事實查詢、只有一個確定步驟的執行題、輸入中沒有可識別的困境。醫療、法律、安全等高風險領域可以借結構生成假設，但不能用類比代替本領域證據。

## Gotchas

- 「團隊溝通」「AI 認知」仍是主題；「怎樣做得更好」又寬得沒有約束。母題必須保留真正的關係或張力。
- 母題不是更抽象的標題。若一句母題仍含兩個以上無法用普通話解釋的承重詞，先解碼，再輸出。
- 母題下只放一個最小示例，用來讓關係第一次執行；不要展開跨域案例清單。
- 預設只設一個貫穿全文的示例錨點。結構卡指回其中的具體瞬間，關係圖串起全域性，風洞改變它的條件；不要在四處重講同一個故事。
- 「像免疫系統」「採用雙盲」只是來源或方案名。拿掉來源名後仍能說清因果，才叫結構。
- 跨域搜尋是內功，不是預設目錄。把三個領域逐項鋪開，往往只會壓住真正的母題。
- 結構卡預設只留一至兩個，第三個必須證明不能併入前兩者。每張卡都要完成「概念明確、關係明確、示例對映」，但不強制顯示成三個欄位。
- 例子必須對映角色與因果。只說「這像某某」會製造熟悉感，不會讓關係變明確。
- 有多個結構時，先判斷它們是串聯、並聯、巢狀、制衡還是反饋，再畫圖；不要看到多個結構就排成鏈。
- 預設不做笛卡爾積、不算組合數。多母題也先找結構關係；只有使用者明確要求組合時才展開。
- 風洞是方法，不是章節。它先鎖定基準預測，再改變一個條件，比較最先出現的差異，最後指出適用邊界和判斷更新規則；成文只保留其中最能改變理解的一次試壓。
- 結論不是全文摘要。它依次完成「具體試壓 -> 抽象規則 -> 回到現象」，讓例子提供抓手，讓抽象關係獲得遷移力。
- 具體試壓與抽象規則必須遞進：前者回答「條件變了會怎樣」，後者回答「這說明哪條更一般的關係」。若兩段只是換詞複述，刪掉較弱的一段。
- 最小可逆實驗只用於行動問題。概念解讀預設給判別檢驗，不把每個思想問題都改造成行動建議。
- 概念模型不能靠事後收窄邊界逃避反例。先宣告適用條件和區別性預測；邊界外案例只負責畫邊界，不算支援或反駁。
- 風洞不引入一套新術語。若必須發明新概念才能解釋試壓結果，先回到結構卡重新解碼。
- 證據邊界只在結尾交代一次。不要在每張結構卡反覆插入警告，打斷推理。
- 不確定事即時，把它留在內部候選層；若必須輸出，明確寫成待核驗，不把記憶中的故事當事實。

## 輸出要求

預設約 800-1500 漢字。一級標題嚴格只有：`輸入`、`母題`、`結構`、`結論`。風洞是內部推理步驟，不作為一級標題輸出。母題用一問一例讓關係先跑起來；結構卡以自然短段完成「概念明確、關係明確、示例對映」，不強制可見欄位。跨域來源不設預設標題；通常不輸出，確有幫助時只用一句話帶一個例子。結構超過一個時，用純 ASCII 連線符畫關係圖，禁止 Unicode 箭頭和方框字元。關係圖後用一句普通話說明「這張圖在例子裡怎樣執行」。

預設取得兩個時間值：`date +%Y%m%dT%H%M%S` 與 `date "+%Y-%m-%d %a %H:%M"`。寫入：

`~/Context/{時間戳}--結構-{主題}__structure.md`

若使用者明確說「只分析」「不落盤」或 `read-only`，直接在對話中給出同等完整的分析，不建立檔案。

檔案必須是 Markdown，禁止 Org 格式。最小結構：

```markdown
---
title: 結構：{主題}
date: [{可讀時間}]
identifier: {時間戳}
tags: structure
---
# 輸入
# 母題
# 結構
# 結論
```

結論用兩段自然收束。第一段回到同一個示例錨點，只改變一個關鍵條件，寫出最先出現的差異以及什麼結果會迫使模型改口。第二段從該差異抽出一條可遷移的關係，直接回答母題，再點回原現象說明現在應該怎樣理解它。末尾只出現一次證據邊界，區分說明性案例、結構推演、本領域已有支援與仍待實驗的部分。儲存後讀迴文件並報告路徑。

## Examples

**Example 1：首個發言者鎖定團隊**

```text
User: 「為什麼團隊討論總被第一個人帶偏？找其中的結構。」
→ 母題用普通話追問：為什麼越早出現的資訊越容易成為後續判斷的參照物？
→ 用會議現場的一句話，讓這條關係先執行一次
→ 結構卡說明「參照物」指什麼、怎樣影響後來者，並給具體例子
→ 內部風洞改變發言順序或資訊來源，比較預測怎樣變化
→ 結論先給出條件變化後的具體差異，再抽出「先出現的資訊會取得解釋權」
```

**Example 2：AI 深挖與異常發現**

```text
User: 「這個 AI 擅長深挖區域性，卻總錯過改變全域性的異常，用結構風洞分析。」
→ 母題：有限注意力如何兼顧區域性開發與未知探索
→ 抽出區域性深挖與外圍巡邏的關係骨架
→ 內部用風洞找出最小異常升級實驗，把試壓結果併入結論
```

**Example 3：使用者明確要求展開**

```text
User: 「請給出這個母題的跨域來源，並分析三個母題怎樣組合。」
→ 才展開來源或多母題處理
→ 仍先判斷結構間的串聯、並聯、巢狀、制衡或反饋並畫圖
→ 只有使用者繼續要求組合數學時，才計算組合空間
```
