# FindStructure

把一段資訊送進結構風洞。風洞在內部執行，預設只輸出真正改變理解的東西：母題、結構關係和經過試壓的結論。

## Step 0 — 充分性檢查

先讀輸入和最近上下文。能識別具體困境就直接做；有歧義但仍可分析時，用一句話說明採用的理解。只有領域名、沒有現象或張力時，最多問三個問題；使用者說 `proceed` 後，明確假設繼續。

## Step 1 — 壓縮輸入

用一小段複述：發生了什麼、想得到什麼、被什麼卡住。只保留決定結構的事實，不把使用者原文換一種說法重抄一遍。

若輸入中有多個現象，先問它們是否由同一個機制生成。能合併就合併，避免把一個問題拆成沉重的清單。

保留至少一個可觀察的錨點：某個人做了什麼、系統出現了什麼變化、判斷在哪一刻失效。若輸入只有抽象命題，沒有現象，後續必須補一個說明性案例來執行結構，並在證據邊界中說明它不是實證。

## Step 2 — 找到母題

母題的目標不是升高抽象度，而是降低詞彙難度，同時保留關係的可遷移性。先拿掉原場景的人名、行業與材料，再用普通話寫成一個具體問題：

> 在 `{關鍵約束}` 下，系統如何處理 `{A}` 與 `{B}` 的關係或張力？

這個句式只供內部定位，不必原樣輸出。成文時：

1. 把 `{關鍵約束}`、`{A}`、`{B}` 換成日常可解釋的詞；
2. 母題第一句只提出一個關係問題，不堆概念；
3. 緊跟一個一至兩句的最小示例，讓這條關係第一次執行，並把它作為全文預設的示例錨點。

優先使用原題中的具體現象。原題只有抽象命題時，才補一個熟悉的說明性案例。例子要明確誰對應 A、誰對應 B、兩者怎樣作用；只說「這像某件事」不夠。

母題過兩道閘：

- **跨域替換**：換掉角色和材料，問題仍成立；
- **解釋回原題**：把原場景放回來，它仍能解釋為什麼會卡住。

再做一次理解檢查：一個沒讀過原文的人，能否只憑母題和示例複述其中的關係？不能就減少抽象詞或更換示例。

預設選一個統攝力最強的母題。若確有多個，不急著做組合；先判斷它們是上下位、前後因果、彼此制衡，還是同一母題的不同側面，並在正文中說明。

## Step 3 — 內部跨域搜尋，提煉結構

在內部搜尋人類制度、自然系統、技術或科學中的同類機制，用來校正和豐富候選結構。來源只是腳手架：預設不輸出來源目錄；確有助於理解時，用一句話帶一個最貼切的例子。

只有使用者明確要求「來源」「跨域例子」「人類或自然怎樣解決」時才展開來源。即使展開，也要迅速回到可遷移的因果骨架，不寫跨學科百科。

合併同構項後，預設只留一到兩個最本質的結構；只有第三個結構無法作為前兩者的步驟、條件、結果或反饋時才保留。結構名稱直接寫在卡片標題中。每張卡都要通過三項語義驗收，但不必顯示成固定欄位：

- **概念**：只解釋一至兩個承重詞。「這裡指什麼」加一個可見標誌，不抄詞典；
- **關係**：用一至兩句寫清 `條件 -> 誰怎樣影響誰 -> 首個變化 -> 結果`；
- **例子**：優先指出母題示例錨點中的哪一瞬間體現了這條關係，並能對應其中的角色和方向。只有錨點無法承載該結構時才補新例子。

成文可用兩三句自然展開，也可在複雜輸入中顯式標註「概念 / 關係 / 例子」；選擇哪種形式，以讀者能否複述模型為準，不為整齊製造模板。

例子不是裝飾。若刪掉結構卡里的抽象詞，只看錨點仍無法說出「誰怎樣影響誰」，說明關係沒有展開。反過來，若錨點只展示相似氣氛、沒有保持角色和因果方向，換掉它。

邊界與預測不再塞進每張結構卡，統一放進內部風洞比較，避免讀者在尚未看懂模型時就被帶去驗證模型。若一個結構只是另一個的步驟、條件或結果，不另立一張卡。

## Step 4 — 判斷結構關係並畫圖

結構超過一個時，先判斷關係，再組織文字：

- **串聯**：前一個結構的輸出觸發後一個；
- **並聯**：多個結構各自處理不同訊號或目標；
- **巢狀**：一個結構規定邊界，另一個在邊界內執行；
- **制衡**：結構彼此限制，防止單邊失控；
- **反饋**：結果反過來增強或削弱原機制。

關係可能混合，不強迫排成鏈。隨後畫一張最小關係圖。連線線、箭頭和方框只用 ASCII 字元，不用 `→`、`┌`、`─` 等 Unicode 圖形字元。例如：

```text
[獨立判斷] --制衡--> [公開匯合]
      ^                    |
      |------ 反饋 --------|
```

圖必須表達真實因果關係，不為好看新增空節點。

圖後補一句普通話：這張圖在示例錨點裡，分別是誰、什麼動作、先後發生了什麼。不要逐節點重抄結構卡或重講故事，只補結構卡沒有呈現的整體關係。

## Step 5 — 風洞校準

風洞是內部判別步驟，不作為可見章節輸出。它讓同一個模型面對不同條件：如果關係是真的，條件變化時預測也應有方向地變化；預測停止成立的地方，就是模型邊界。完成後只把最有區分力的一次條件變化、首個差異和改口訊號交給結論。

### 5.1 鎖定基準預測

沿用前文的示例錨點，用一句話鎖定關鍵關係的基準預測：

```text
觸發條件 -> 關鍵作用 -> 首個可觀察變化 -> 最終結果
```

只使用結構卡里已經解釋過的概念。這一步只回答「在原條件下，模型預測什麼」，不再複述場景、定義或完整因果鏈。

### 5.2 改變一個條件

選擇對結果最關鍵、又能自然變化的一個條件，例如資訊出現的早晚、反饋強弱、參與者是否獨立、資源多少或作用持續時間。讓它變強、變弱、提前、延後或進入另一個範圍，然後寫清：

1. 條件怎樣變化；
2. 模型預測最先出現什麼不同；
3. 這個變化如何傳到最終結果；
4. 若結果沒有按方向變化，哪條關係需要重寫。

不必製造災難性結局。風洞的價值在於比較相鄰條件下的差異，使因果方向和有效範圍變得可見。

### 5.3 找到邊界與改口條件

先宣告模型適用的條件，再選擇相稱的檢驗：

- **概念或解釋問題**：比較一個範圍內案例和一個邊界案例。事先寫出區別於替代解釋的預測；若條件成立而預測未出現，或替代解釋命中而本結構沒有命中，就修改判斷。邊界外案例只標記範圍，不算支援或反駁。
- **行動或系統問題**：使用者需要行動時，才給最小可逆實驗。只改變一個條件，寫清觀察訊號、支援訊號、反駁訊號與停止條件。

內部風洞完成後應能回答：

1. 模型在基準場景中怎樣執行？
2. 一個關鍵條件變化後，預測怎樣變化？
3. 在什麼邊界或觀察面前，我們必須修改判斷？

任一問題答不出時，優先補一個具體動作、對照場景或改口訊號，不要再增加抽象概念。不要把完整試壓過程搬進成文；結論只保留能使抽象規則變得可見、可辨、可改口的部分。

只有使用者明確要求「多母題組合」「結構組合」「窮舉解法」時才展開組合。即便如此，也先畫母題與結構關係圖，識別串聯、並聯、巢狀、制衡和反饋；只有使用者進一步要求組合數學、搜尋規模或窮舉，才計算組合數。

跨域來源與組合擴充套件都放在預設四個一級標題之下作為二級內容，不新增一級標題。

## Step 6 — 寫成 Markdown 筆記並自檢

預設寫入 SKILL.md 指定的 Markdown 路徑；使用者明確說「只分析」「不落盤」或 `read-only` 時，按同樣結構在對話輸出，不建立檔案。

一級標題嚴格只有：

```markdown
# 輸入
# 母題
# 結構
# 結論
```

預設約 800-1500 漢字。檢查：母題不是主題換名，且用普通話與一個最小示例讓關係執行；全文預設只有一個示例錨點；結構卡每個都完成概念、關係、示例三項語義驗收，但沒有為整齊強制欄位；多個結構已經判關係並有純 ASCII 圖，圖後只補整體對映；沒有預設來源清單、笛卡爾積或組合數；內部風洞已經包含基準預測、一個條件變化、預測差異、邊界與改口訊號，成文沒有單列風洞標題。只有行動問題才預設檢查最小可逆實驗。

### 6.1 結論收束

結論不總結全文，而是把內部風洞壓縮成兩段遞進：

1. **具體試壓**：回到同一個示例錨點，只改變一個關鍵條件，寫出最先出現的差異；緊接著說明什麼觀察會使這套解釋失效。不要重講完整故事，也不另舉新例。
2. **抽象與回扣**：從上述差異中抽出一條可遷移的關係，直接回答母題；隨後點回原現象的決定性瞬間，說明這條抽象規則具體讓讀者多看見了什麼。

兩段必須構成「現象差異 -> 一般關係」的推導。若抽象規則不能解釋前一段的具體差異，說明例子沒有承載關係；若前一段只是把抽象規則換成口語再說一遍，說明具體抓手仍然缺失。行動建議只在使用者的問題本來需要行動時出現。

在結論末尾只寫一次證據邊界，合併說明哪些案例僅用於展示關係、哪些屬於結構推演、哪些已有本領域證據支援、哪些仍待實驗。不要在每張結構卡重複證據標籤。

最後做一次理解檢查：

- 只讀具體試壓，能否看見條件、變化方向和改口訊號？
- 只讀抽象規則，能否把它遷移到原場景之外？
- 把兩段連起來，能否說清「這個現象為什麼支援這條關係」，而不只是覺得例子很像？

儲存時讀回檢查並報告路徑；只分析時註明未落盤。
