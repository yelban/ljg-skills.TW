# ljg-map · 形式化思考地圖

用《學習觀》關於概念、判別模型和聯結模型的理解，看到文稿背後的知識結構：哪些詞有明確的所指，現實物件憑什麼歸入它們，概念之間的關係在什麼條件下成立。把看到的結構畫出來，形式化負責減少歧義，白話和例項負責讓關係可理解、可使用。

## Workflow Routing

| 請求 | 執行 |
|---|---|
| 從文稿生成地圖，或修訂已有地圖 | 閱讀 [Workflows/Map.md](Workflows/Map.md) |
| 需要校準公式密度、節點解釋和來源邊界 | 按需閱讀 [Examples.md](Examples.md)；學習表達方式，不套用題材和節點 |

## Gotchas

- **知識觀是洞察視角，圖形由材料決定。** 具象、概念與應用的對應幫助檢查知識是否接通，不構成固定的三個圖層、三個欄目或必經步驟。分類交叉就畫交叉關係，反饋就畫迴圈；材料確有層級時才畫層級。
- **節點來自當前文稿。** 不把任何文章都畫成「經驗—抽象—概念—記憶—學習」；只有文章本身討論這些概念時，它們才成為內容節點。判別、驗證可以寫在邊或節點解釋裡，無須一律佔框。
- **地圖不是換成公式的長文。** 成品先讓讀者看見承重關係，再解釋圖裡的節點。不能只給概念清單、長表格或一串沒有地圖的公式。
- **形式化不以符號數量計。** 優先「中文名稱 + 短公式」。定義符號後再使用，不另造一套圖論元語言來描述本來很簡單的文章。
- **分類與預測分開。** 「有圓圈」可以定義一類；「這一類會加分」是另一條需要依據的關係。滿足分類條件不自動證明預測成立，也不能推出反面類別有反面結果。
- **箭頭有語義。** 定義、歸類、計算、相關、因果、類比、推斷和反饋不能混作一種關係；用短邊標籤和必要條件區分。猜想仍標猜想。
- **圖的完整不能靠編造。** 文稿缺少判別標準、例項或驗證辦法，就在對應位置標缺口。補充的教學例子、應用設想與可行性判斷要與原文陳述分清。

## 成品約定

預設直接在對話中交付 Markdown、Mermaid 和可讀公式。使用者要求儲存、特定格式或修改已有產物時，按其指定交付；本技能不預設寫筆記、覆蓋原文或釋出。

主圖顯出這篇文稿特有的知識關係，不預設層數、形狀或統一應用流程。主要關係保持易讀，次要分支可以放到有連線位置的補圖或標記表。每個圖中節點均能在解釋中找到相同編號或名稱，以及定義、公式、語義和具體對應。

## Examples

- `/ljg-map <文稿或檔案路徑>`：讀到實際內容後，畫出該文稿的知識結構，解釋每個節點，用合適的具體對應講清關鍵關係。
- `把這篇文章的概念、判別和聯結畫清楚，別改寫文章`：保留作者的主要推理、並列結構及重要分歧；在箭頭處標明條件和來源中的不確定性。
- `這張圖太難懂，重新畫`：減少符號和主圖擁擠度，用一個合適例子貫穿；保留會改變判斷的條件，不以刪掉論點換取表面簡潔。
