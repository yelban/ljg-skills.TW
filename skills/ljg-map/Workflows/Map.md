# 洞察並畫出文稿的知識結構

## 輸入與交付範圍

物件是使用者提供的文稿、節選、已有筆記或對話中的明確內容。檔案要讀取正文；連結要獲得實際內容。只取得部分材料時，地圖範圍限於已讀部分。輸入無法取得，或不清楚指的是哪份材料時，詢問缺少的內容；不從標題臆造全文。

當前任務是提煉思考結構，不預設改寫原文、查證整本書或補成一篇新論說。需要校準影響關鍵關係的事即時，可使用當前環境可用的來源工具；區分「原文主張」「有依據的校準」與「為理解補充的設想」。

## 洞察所用的知識觀

《學習觀》提供的是辨認知識的視角：抽象保留某些屬性，概念劃定物件；判別模型把具體物件接入概念，聯結模型描述概念之間的關係。一個人能複述關係，不代表能識別適用物件；例項與關係脫節或錯接，都會讓看似完整的知識失效。

用這些區別理解當前文稿，而不把書中的術語直接當作輸出節點：

| 所看之處 | 要辨明什麼 | 圖中的落點由內容決定 |
|---|---|---|
| 概念 | 名字指什麼，保留了哪些屬性，忽略了哪些差異？ | 通常是內容節點；連續變數、狀態和過程也各有適合的定義 |
| 判別 | 一個具體物件滿足什麼條件才能歸入該概念，證據不足怎麼辦？ | 可放在定義、例項標註、條件邊中；只有識別過程本身重要時才獨立成節點 |
| 聯結 | 概念之間有什麼關係，其方向、條件與依據是什麼？ | 決定連線、公式，以及整張圖的形狀；保留集合、數量、因果、約束、張力等不同關係 |
| 現實對應與檢驗 | 關係對應哪些例項，能推出什麼，又會被什麼證據推翻或收窄？ | 用例子與邊界把關係講實；需要時才畫應用路徑或反饋節點 |

具象層、概念層、應用層是檢查知識聯絡的背景理解，不是排版要求。成品可以是一張交叉分類圖、守恆關係圖、條件分支圖、反饋環或多種關係相接的網路；這些只是可能形狀，不是必須逐項嘗試的選單。結構由實際關係長出，不先選漂亮形狀再填名詞。

同一概念保持同名和同一定義。關鍵概念有可理解的所指，關鍵關係有成立條件；如果這些聯絡缺失，就在對應位置留下缺口。原文適合演示遷移時，讓一個情境沿關係走通；純分類或比較材料可以靠成員與邊界案例說明，不強加預測、行動、驗證的通用流水線。

## 可讀的地圖

成品通常由一句主判斷、少量符號說明、主圖、節點解釋以及必要的邊界組成。按內容調節順序和篇幅，不填固定欄目。

- 主圖使用能準確顯出關係的表示。通常用 Mermaid；集合交叉、二維分類或約束區域用其他清楚的文本圖或座標表示也可以。分組、層級和佈局均由內容決定，不預設建立三個 subgraph，也不把所有關係變成流程圖。主圖放主論點和承重關係，支線過多時拆分，並註明接回主圖的位置。
- 節點以普通中文命名，可帶穩定編號和一行短定義式。長公式移到同名節點解釋。只為後續真的用到的符號作說明，不預設固定節點數或符號數。
- 箭頭標明「據此歸類」「在條件…下」「預測」「比較」「修正」等真實關係；閱讀順序和時間先後不能冒充因果。定義邊、作者假設和實證支援的關係按需區分。
- 有獨立分支或反方主張時保留其位置。不能為了一個貫穿故事，把不同案例合成未發生過的事實，也不能用一個順暢例子取代全文主線。

## 每個節點的可用定義

每個圖中節點，包括輔助節點，都有可對應的解釋。通常用短段落承載以下內容；只有並列資訊很短時才用表格。

**白話定義**：它是什麼，邊界在哪裡。類別說成員條件，變數說量的含義和必要單位，過程說輸入如何變成輸出。用途和比喻不能代替定義。

**短公式**：以最少的符號明確條件、對應或運算。每個符號有同處或先前給出的含義，整句能翻回普通話。不同性質的節點不用同一種公式硬套。

| 物件 | 可選寫法 | 含義 |
|---|---|---|
| 類別 | `C := {x : x 滿足條件 Q}` | 這類包含哪些物件 |
| 變數 | `等待時間 := 開始處理時刻 − 到達時刻` | 具體在量什麼，單位一致 |
| 判別 | `判別(x) ∈ {屬於, 不屬於, 不確定}` | 根據證據判斷是否滿足條件 |
| 確定關係 | `條件成立 ⇒ 結果成立` | 保留原文承諾的方向與適用條件 |
| 待驗關係 | `條件 —待驗證預測→ 結果` | 提出了可檢查的推測，尚未證明 |
| 應用 | `情境 → 歸類/對應變數 → 使用關係 → 情境中的結論` | 展示上下層怎樣接通 |
| 驗證 | `預測結果 ≟ 獨立觀察到的結果` | 檢查模型在所測條件下是否有效 |

**具體語義**：用一個與材料相符的物件或場景解釋公式中各部分對應什麼，說明它如何參與相鄰關係。材料涉及判斷或行動時，再說明它改變了哪一步選擇。優先沿用少量貫穿案例；關鍵的另一分支需要自己的例子時再新增。補充設例要就地標註。

**必要邊界**：足以改變歸類、關係或行動的例外，應緊貼節點或連線。沒有證據時允許「不確定」；沒有定義的閾值保留為未知，不替作者隨意補數。關係可能只是相關、傾向或規範，不升級為必然因果。

## 形式化需要保留的區別

- 定義決定詞如何使用，經驗規律需要證據。`C := 滿足 Q 的物件` 與 `C 會產生 Y` 是兩件事。
- 人的實際判別可能出錯；會複述條件並不保證能在新情境識別。公式中的變數對應也要展示，不能把「會計算」當成已經接通現實。
- `A ⇒ B` 不自動給出 `非 A ⇒ 非 B` 或 `B ⇒ A`。把必要條件當充分條件、把相似當等同，會改變圖的結論。
- 連續變數與數值關係保留單位和範圍；不把所有概念都改造成非黑即白的分類。
- 一個正例不證明普遍關係；圖上的「驗證」表示檢查方法或有限證據，不自動等於已通過。補充的測試情境在揭曉結果後就不再是獨立的未見測試。
- 正確結論不能單獨證明前提與對應正確。錯誤可以發生在判別、變數對應、聯結、條件檢查或結果解釋中。
- 原文有修辭或模餬口號時，給出它允許的最清楚表達，並標明尚缺的定義或關係。不要用無量綱的乘法、加法或精確機率裝飾它；若用「＋」表示組成，明確這是組成記號。

## 讀回標準

交付前讀回圖、節點解釋與原文：主論點和重要分支是否仍在，節點與編號是否一一對應，每條關鍵邊的方向與條件是否有依據。讀者應能用具體物件說明核心概念與關係，並辨認成立條件或未決處。尤其檢查：圖的分組和走向是否來自這篇文稿，還是把分析時使用的視角誤畫成了物件自身的結構。

能解析的圖不等於正確或易讀的圖。若只檢查了 Mermaid 語法，不聲稱已做視覺驗收。預設對話交付不另外製作圖片、網頁或筆記；使用者要求相關產物時，再按對應格式完成實際驗證。
